# BLUEPRINT RPM - RPP_MODULE_AJAR_RPL

Project: RPP_MODULE_AJAR_RPL
Tanggal: 2026-07-24

## Status proyek

Project ini disiapkan untuk menyusun **RPM (bukan lagi RPP)** dan modul ajar RPL dengan pendekatan **Pembelajaran Mendalam / Deep Learning**.

## DNA utama yang harus dipakai

### 1. Pembelajaran Mendalam
Seluruh desain RPM dan modul ajar harus mengikuti alur:
- **Memahami**
- **Mengaplikasi**
- **Merefleksi**

### 2. Fase pembelajaran
- **Kelas X = Fase E**
- **Kelas XI = Fase F**
- **Kelas XII = Fase F**

### 3. Mata pelajaran target
Blueprint ini disiapkan untuk **mata pelajaran produktif**, bukan mapel umum.

## Prinsip desain RPM

RPM harus menjadi dokumen yang menjawab:
- murid memahami apa,
- murid mengerjakan apa,
- murid membuktikan apa,
- murid merefleksi apa.

RPM harus menjadi peta kerja yang jelas bagi guru dan murid.

## Struktur isi RPM yang akan dipakai

### A. Identitas / Informasi umum
Berisi data dasar pembelajaran, misalnya:
- satuan pendidikan,
- program keahlian,
- mata pelajaran,
- fase,
- kelas/semester,
- alokasi waktu,
- topik / elemen CP,
- profil murid,
- prasyarat.

### B. Capaian Pembelajaran / Tujuan
Berisi:
- CP yang dipilih,
- tujuan pembelajaran yang diturunkan dari CP dan ATP,
- tujuan yang konkret dan terukur.

### C. Pemahaman bermakna
Berisi:
- makna inti yang harus dipahami murid,
- hubungan materi dengan dunia nyata / dunia kerja / proyek,
- alasan mengapa materi ini penting.

### D. Pertanyaan pemantik
Berisi pertanyaan yang:
- memancing rasa ingin tahu,
- membuka diskusi,
- mengantar murid ke pemahaman konsep.

### E. Pengalaman belajar utama (3M)
Berisi alur pengalaman belajar:
1. **Memahami**
   - observasi,
   - membaca,
   - diskusi,
   - penjelasan konsep.
2. **Mengaplikasi**
   - praktik,
   - tugas,
   - proyek mini,
   - kerja individu/kelompok.
3. **Merefleksi**
   - umpan balik,
   - jurnal refleksi,
   - perbaikan hasil kerja.

### F. Asesmen
Berisi:
- asesmen awal,
- asesmen proses,
- asesmen hasil,
- rubrik jika diperlukan.

### G. Sumber belajar / referensi
Berisi:
- buku / dokumen rujukan,
- sumber resmi,
- file contoh,
- tautan pendukung.

## Layout dokumen yang harus dibuat

RPM harus disusun rapi sebagai dokumen siap baca. Urutan layout yang direkomendasikan:

1. Judul / identitas dokumen
2. Informasi umum
3. CP dan tujuan pembelajaran
4. Pemahaman bermakna
5. Pertanyaan pemantik
6. Langkah pembelajaran 3M
7. Asesmen
8. Pengayaan / remedial bila diperlukan
9. Sumber belajar / referensi
10. Catatan refleksi guru

## Catatan khusus DDPK (Dasar-Dasar Pengembangan Perangkat Lunak dan Gim)

- Bro Cahyo menambahkan file ATP DDPK jurusan RPL sebagai sumber utama analisis.
- File referensi ada di folder `01 SUMBER` dan juga harus di-drive-kan ke Google Drive.
- Mata pelajaran DDPK dilakukan selama **2 semester**.
- Beban belajar: **12 JP per minggu**.
- Satu tahun ajaran: **36 minggu**.
- Harus dibuat hasil analisis untuk perencanaan RPM/RPP per tatap muka.
- Dokumen input menampilkan tahapan materi 1 s.d. 4 serta tabel Elemen, CP, TP, dan ATP.
- Untuk RPP/RPM berikutnya, struktur analisis per pertemuan harus mengikuti ATP ini.
